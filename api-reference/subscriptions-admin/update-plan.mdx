---
title: "Update plan"
description: "Patch a subscription plan from the admin console."
api: "PATCH /api/subscriptions/plans/:id"
---

Partially updates a plan. Same field semantics as the tenant-side [`PATCH /v1/plans/:id`](/api-reference/subscriptions-tenant/update-plan), but no per-application scoping — admins can edit any plan. Writes a `subscriptions.plan_updated` audit row with the list of changed fields.

Requires an admin bearer token with the `subscriptions:write` scope.

## Path parameters

<ParamField path="id" type="string" required>Plan ID, e.g. `plan_pro`.</ParamField>

## Body

All fields optional.

<ParamField body="name" type="string">Display name.</ParamField>
<ParamField body="slug" type="string">Stable identifier.</ParamField>
<ParamField body="description" type="string">Description.</ParamField>
<ParamField body="interval" type="string">`weekly | monthly | quarterly | annual`.</ParamField>
<ParamField body="price" type="number">Minor units.</ParamField>
<ParamField body="currency" type="string">`GHS` or `USD`.</ParamField>
<ParamField body="trial_days" type="number">Trial length.</ParamField>
<ParamField body="features" type="string[]">Feature bullets.</ParamField>
<ParamField body="max_seats" type="number">Seat count.</ParamField>
<ParamField body="paystack_plan_code" type="string">Paystack plan code.</ParamField>
<ParamField body="active" type="boolean">Availability flag.</ParamField>

## Query parameters

<ParamField query="force" type="boolean" default="false">
  Only consulted when the request sets `active=false`. When `true`, suppresses the `warning` payload below. Does **not** change the destructive action — the plan still deactivates either way; only the warning is silenced.
</ParamField>

## Response

`200 OK`.

<ResponseField name="success" type="boolean">Always `true`.</ResponseField>

<ResponseField name="warning" type="object">
  Only present when the request set `active=false` and the plan has existing dependents. Contains:

  - `warning` (string) — always `"plan_has_active_subscriptions"`.
  - `active_subscriptions` (number) — count of subscriptions currently on this plan in non-terminal state.
  - `pending_checkouts` (number) — count of checkout sessions that reference this plan and haven't yet converted or expired.
  - `advice` (string) — operator-facing guidance copy.
</ResponseField>

<Note>
  Plan deactivation is **never blocked** — admins retain the lever even if there's outstanding activity. The warning exists so the admin can see what they're about to disrupt before it lands. Pass `?force=true` to deactivate without surfacing the warning (e.g. when scripting cleanup).
</Note>

```json Example response with warning
{
  "success": true,
  "warning": "plan_has_active_subscriptions",
  "active_subscriptions": 47,
  "pending_checkouts": 3,
  "advice": "Migrate these subscriptions to another plan before deactivating, or pass ?force=true to suppress this warning."
}
```

## Errors

| Status | Code | When |
|--------|------|------|
| 400 | `no_fields` | Body had no recognized fields. |
| 404 | `not_found` | Plan doesn't exist. |

<CodeGroup>

```bash curl
curl -X PATCH "https://auth.mgpass.net/api/subscriptions/plans/plan_pro" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "active": false }'
```

```typescript TypeScript
await fetch("https://auth.mgpass.net/api/subscriptions/plans/plan_pro", {
  method: "PATCH",
  headers: {
    Authorization: `Bearer ${adminToken}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ active: false }),
});
```
