---
title: "Refund payment"
description: "Issue a refund through the original payment provider and cancel the subscription."
api: "POST /api/subscriptions/:id/refund"
---

For Paystack-funded payments, calls Paystack's `POST /refund` API with the original `transaction` reference, records a negative-amount `subscription_payments` row (`payment_type=refund`, `status=refunded`, `provider_reference` set to Paystack's refund id), cancels the subscription immediately, and writes a `subscriptions.refund_issued` audit row.

For Hubtel-funded payments — or when no original payment row is found — the endpoint falls back to recording the local refund row + cancelling the sub, with the audit metadata flagging `auto_refund: false` so it's clear a manual MoMo refund is still required.

The Paystack refund itself is queued by Paystack and settles asynchronously; a successful 200 here means "we kicked it off successfully," not "the money has landed back in the customer's bank." Listen for Paystack's `refund.processed` webhook to confirm settlement.

Requires an admin bearer token with the `subscriptions:write` scope.

## Path parameters

<ParamField path="id" type="string" required>Subscription ID.</ParamField>

## Body

<ParamField body="amount" type="number" required>
  Refund amount in minor units (pesewas/cents). Must be positive. Paystack will refund this exact amount up to the original transaction total.
</ParamField>

<ParamField body="reason" type="string">
  Free-form reason. Captured on the payment row's `failure_reason` column, passed to Paystack as `merchant_note`, and written to the audit log.
</ParamField>

<ParamField body="payment_id" type="string">
  Specific subscription payment to refund. If omitted, the most recent succeeded payment on the subscription is selected.
</ParamField>

## Response

`200 OK`.

<ResponseField name="success" type="boolean">Always `true`.</ResponseField>
<ResponseField name="provider" type="string">`paystack` | `hubtel` | `none`.</ResponseField>
<ResponseField name="paystack_refund_id" type="string">Returned when `provider=paystack`. The refund id from Paystack — useful for correlating with their `refund.processed` webhook.</ResponseField>
<ResponseField name="auto_refund" type="boolean">`true` when the provider was called (paystack); `false` when the refund was recorded locally only (hubtel or no original payment).</ResponseField>

## Errors

| Status | Code | When |
|--------|------|------|
| 400 | `invalid_request` | `amount` is missing or `<= 0`. |
| 404 | `not_found` | Subscription doesn't exist. |
| 404 | `payment_not_found` | `payment_id` provided but doesn't belong to this subscription. |
| 502 | `paystack_refund_failed` | Paystack rejected the refund (e.g. transaction already refunded, insufficient balance). The subscription is NOT cancelled and no local refund row is written — retry with a different `payment_id` or escalate to Paystack support. The audit log records the failure. |

<CodeGroup>

```bash curl
curl -X POST "https://auth.mgpass.net/api/subscriptions/sub_xyz/refund" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "amount": 2500, "reason": "Duplicate charge" }'
```

```typescript TypeScript
const res = await fetch("https://auth.mgpass.net/api/subscriptions/sub_xyz/refund", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${adminToken}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ amount: 2500, reason: "Duplicate charge" }),
});
const { provider, paystack_refund_id, auto_refund } = await res.json();
```
