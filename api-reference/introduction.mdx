## Base URL

| Environment | URL |
|-------------|-----|
| Production | `https://auth.mgpass.net` |

The hosted checkout page is served from `https://pay.mgpass.net` (same mgPass authorization service, different route).

## Authentication

mgPass uses three authentication methods. Each endpoint group below states which one it expects.

<CardGroup cols={3}>
  <Card title="OAuth Bearer access_token" icon="user">
    End-user identity. Issued by the OAuth flows. Carries scopes — gates `/api/account/*` and userinfo.
  </Card>
  <Card title="Admin Bearer token" icon="shield">
    Operator identity. Bearer token with the `mgpass:admin` scope. Gates the entire management API.
  </Card>
  <Card title="X-API-Key" icon="key">
    Tenant / partner server identity. Static per-capability key in the `X-API-Key` header. Gates `/v1/*` and `/api/partner/events`.
  </Card>
</CardGroup>

### Examples

<CodeGroup>

```bash User Bearer
curl https://auth.mgpass.net/api/account/profile \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

```bash Admin Bearer
curl https://auth.mgpass.net/api/applications \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

```bash X-API-Key
curl https://auth.mgpass.net/v1/plans \
  -H "X-API-Key: $TENANT_API_KEY"
```

</CodeGroup>

## Money and currency

All money fields are integers in **minor units** — pesewas for `GHS`, cents for `USD`. Every money-bearing request, response, and webhook payload carries an explicit `currency` ("GHS" or "USD") alongside the `amount`.

```json
{
  "amount": 5000,
  "currency": "GHS"
}
```

This is 50.00 GHS, not 5000 GHS.

<Note>
  `GHS` is the default for plans and the only currency Hubtel MoMo accepts. `USD` plans require a card payment provider (Paystack merchant-multi-currency-enabled). Annual plans are card-only regardless of currency.
</Note>

## Response format

Successful responses return JSON. Paginated endpoints follow this shape:

```json
{
  "results": [...],
  "total": 150,
  "page": 1,
  "page_size": 25
}
```

## Errors

Errors return the standard JSON error shape with an appropriate HTTP status:

```json
{
  "error": "validation_failed",
  "message": "currency must be GHS or USD",
  "details": { "field": "currency" }
}
```

See [Error handling](/guides/error-handling) for the full code table, retry strategy, and idempotency guidance.

## Rate limits

| Endpoint | Limit |
|----------|-------|
| Partner events | 30 req/min per IP |
| Checkout creation | 60 req/min per Application |
| General API | 100 req/min per IP |

Webhook delivery uses an internal retry queue with exponential backoff — your endpoint does not need to be available at the moment of the event.
