---
title: "Create User"
api: "POST /api/users"
---

Creates a user directly, without the sign-up flow. Use it for seeding, migrations and support-created accounts.

Requires an admin bearer token.

<Note>
  The new account starts with `email_verified: false` and `phone_verified: false`, and a verification email **is** sent to the address you supply. Default user roles are assigned automatically.
</Note>

## Body

<ParamField body="email" type="string" required />

<ParamField body="password" type="string" required />

<ParamField body="name" type="string" />

<ParamField body="phone" type="string" required>
  Required. Ghanaian mobile number, in local (`024 123 4567`) or international (`+233241234567`) form — both are normalised to `+233` before storage. Stored **unverified**: collecting a number and proving ownership of it are separate steps, and nothing that depends on ownership accepts an unverified number.

  `users.phone` is unique, so a number already held by another account — including a soft-deleted one — is refused with a 409.
</ParamField>

<ResponseField name="id" type="string" />

<ResponseField name="email" type="string" />

<ResponseField name="email_verified" type="boolean" />

<ResponseField name="phone" type="string" />

<ResponseField name="custom_data" type="object">
  Arbitrary JSON you store against the user, returned parsed. An empty object when none was set.
</ResponseField>

<ResponseField name="is_suspended" type="boolean" />

<ResponseField name="suspension_reason" type="string" />

<ResponseField name="created_at" type="string">
  ISO 8601. This endpoint returns timestamps as strings, not the epoch seconds used elsewhere in the API.
</ResponseField>

<ResponseField name="last_sign_in_at" type="string">
  ISO 8601. Derived from the most recent session when the column was never stamped.
</ResponseField>

<ResponseField name="deleted_at" type="string" />

<ResponseField name="roles" type="array">
  Returned by the single-user endpoint, not by the list.
</ResponseField>

## Errors

| Status | Code | When |
|--------|------|------|
| 400 | `invalid_request` | `email` is missing or malformed, `password` fails the strength rules, or `phone` is missing or not a valid Ghanaian mobile number. |
| 409 | `invalid_request` | The email or the phone number is already registered. The `error_description` says which. |
| 401 | `unauthorized` | Missing or invalid admin token. |

<Warning>
  Both duplicate cases return the code `invalid_request` and differ only by HTTP status (409) and `error_description`. Branch on the status and read the description — do not assume a 409 means the email.
</Warning>
