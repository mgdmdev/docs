---
title: "RP-Initiated Logout"
api: "GET /logout"
---

Ends the user's mgPass session for the current browser and (optionally) redirects
back to your app. Also available as `POST /logout` (form or JSON body).

## Query parameters

<ParamField query="id_token_hint" type="string">
  The `id_token` you received at login. Identifies the user and your app (its
  `aud`). Expired tokens are accepted. A **verified** hint is required to revoke
  the user's session / offline access — a forged or unsigned hint only clears the
  caller's own cookie.
</ParamField>

<ParamField query="client_id" type="string">
  Your application (client) ID — an alternative to `id_token_hint` for
  identifying the RP so the post-logout redirect can be validated.
</ParamField>

<ParamField query="post_logout_redirect_uri" type="string">
  Where to send the user after logout. Must **exactly match** one of your
  application's registered `post_logout_redirect_uris` (a trailing-slash
  difference is tolerated). If it doesn't match — or the RP can't be identified —
  mgPass returns `{"success": true}` instead of redirecting (open-redirect
  protection).
</ParamField>

## Behavior

- Clears the shared `.mgpass.net` session cookie for this browser.
- Refresh-token revocation is **scoped to the identified client** — logging out
  of one app does not revoke another app's offline access.
- On a valid, registered `post_logout_redirect_uri`, responds `302` to it;
  otherwise `200 {"success": true}`.

<Note>
Save the `id_token` from the token exchange so you can pass it as `id_token_hint`.
If you only have the `client_id`, pass that instead — the redirect is still
validated against your registered URIs.
</Note>
